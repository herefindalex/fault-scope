# Human language translations

Human Locale and Code Lens are independent. Locale selects prose and layout;
Code Lens selects one of the seven shared source artifacts. The canonical Case
identity, step and question IDs, options, visual states, and contracts remain in
`web/src/case-data.json` and `web/src/case.ts`. Locale content cannot change
the reducer or code snippets.

The project uses a small typed JSON catalog instead of an i18n framework.
The interaction is client side, all routes are statically exported, and there
is no production Node server. The catalog keeps the build dependency surface
small while allowing message-level fallback and build-time validation.

## Status and fallback

`web/i18n/registry.json` lists each locale's ID, native and English names,
direction, and status. English is the complete source locale. The other 19
locales are **beta, unreviewed, and incomplete**. Their existing translations
were generated during implementation and have not been reviewed by a native
speaker or distributed systems specialist. Missing beta messages fall back to
English at the message level in production. Development displays a visible
`[MISSING: key]` marker beside the English source. Beta pages are accessible
but carry `noindex` and are omitted from the sitemap until fully translated
and reviewed. Do not change a locale to `reviewed` until its entire shared UI
and Case content have been checked for technical meaning; validation then
requires all source keys and canonical step IDs.

## Editing a translation

1. Choose a locale in `web/i18n/registry.json`.
2. Edit shared UI in `web/i18n/messages/<locale>.json` and Case 01 prose in
   `web/content/cases/fs-c01/locales/<locale>.json`. Keep semantic IDs and
   interpolation placeholders unchanged. Do not translate route slugs or
   duplicate source code for a Human Locale.
3. Run `go run ./tools check --locale <locale>`. This needs Go only and does
   not invoke the seven Code Lens compiler suites.
4. With Node 24 and pnpm 12, preview with
   `go run ./tools dev --open --locale <locale> --case fs-c01 --language cpp`.
   Check Guided, Challenge, Deep Dive, the locale selector, and RTL layout if
   relevant. Run `go run ./tools check` before submitting.

Changing any locale content changes the static export bytes, which changes
the embedded bundle's `content_hash`. The Go executable is the production
runtime; there is no translation server or Node runtime.

## Routes and search metadata

Routes use stable slugs: `/ja/`,
`/ja/cases/should-you-send-it-again/`, and `/ja/languages/cpp/`.
The root `/` chooses saved locale, then browser language, then English,
and provides static locale links without JavaScript. A localized URL is always
explicit and wins over stale browser preference. Locale selection saves
`faultscope.v1.locale`; Code Lens uses `faultscope.v1.codeLens` and an
optional `?lang=` override. Case progress uses
`faultscope.v1.caseProgress.fs-c01` across localized URLs.

Set `FAULTSCOPE_SITE_URL` to the public site origin **at build time** to
generate production canonical, alternate, and sitemap URLs. It defaults to
`http://localhost:8080` for local builds because this repository has no
configured public site origin yet.
