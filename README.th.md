**ห้องทดลองแบบโต้ตอบเพื่อเรียนรู้ความถูกต้องของแอปพลิเคชันแบบกระจาย**

FaultScope เริ่มจากหลักฐานและข้อตกลงของระบบ เพื่อพิจารณาว่าหลังเกิดข้อขัดข้องยังรับประกันอะไรได้บ้าง แต่ละกรณีจะระบุคุณสมบัติที่ต้องรักษาไว้ก่อน แล้วจึงหาจุดที่ต้องแก้ไข

## สำรวจทั้งแปดกรณี

1. [คุณควรส่งอีกครั้งหรือไม่?](docs/cases/fs-c01.md) — ไม่ได้รับคำตอบ แต่ VM อาจถูกสร้างไปแล้ว สัญญาการทำงานจะบอกว่าทำอะไรต่อได้อย่างปลอดภัย
2. [หลัง B รับช่วงงานแล้ว A ยังบันทึกผลได้ไหม?](docs/cases/fs-c02.md) — Worker B รับช่วง Job J แล้ว แต่ A ยังทำงานอยู่ การตรวจสอบที่ Job Store จะตัดสินว่าผลของ A ยังมีผลหรือไม่
3. [ยืนยันคำสั่งซื้อแล้ว Event E อยู่ไหน?](docs/cases/fs-c03.md) — Order42 เป็น CONFIRMED ใน PostgreSQL แต่โปรเซสล้มก่อนเผยแพร่ Event E จะมีบันทึกถาวรใดรับประกันว่า E ยังถูกเผยแพร่ภายหลัง?
4. [ตัวรับข้อความทำงานเสร็จแล้ว ทำไมจึงทำงานอีกครั้ง?](docs/cases/fs-c04.md) — รางวัลที่มุ่งมั่นและการตอบรับที่ขาดหายไปสามารถทำให้เหตุการณ์เชิงตรรกะหนึ่งเหตุการณ์มาถึงสองครั้งได้
5. [เหตุการณ์ใดใหม่กว่ากันแน่?](docs/cases/fs-c05.md) — การจัดส่งในภายหลังสามารถมีสถานะเก่ากว่าได้ ค้นหาหน่วยงานที่สั่งซื้อเปลี่ยนแปลงเป็นการจัดส่งครั้งเดียว
6. [อ่านข้อมูลสำเร็จ แต่ข้อมูลใหม่พอหรือยัง?](docs/cases/fs-c06.md) — การตอบกลับที่ประสบความสำเร็จอาจยังเก่าเกินไปสำหรับผู้โทรรายนี้ ดำเนินการแก้ไขที่มุ่งมั่นในสัญญาการอ่าน
7. [การยกเลิกหยุดงานได้จริงหรือ?](docs/cases/fs-c07.md) — สัญญาณการยกเลิกมาถึงแล้ว แต่แฮนด์ออฟผลลัพธ์ยังคงถูกบล็อกอยู่ ค้นหาปฏิบัติการที่ต้องเข้าร่วม
8. [ระบบเริ่มทำงานใหม่ แล้วลืมอะไรไป?](docs/cases/fs-c08.md) — Shipment42 ยังคงพูดว่า SHIPPED หลังจากเกิดอุบัติเหตุ การ์ดแก้ไขที่ปกป้องมันหายไปแล้ว

แต่ละกรณีมีโหมดแนะนำ ท้าทาย และเจาะลึก ภาพอธิบายเฉพาะกรณี แผงหลักฐาน / ข้อตกลง / คุณสมบัติ และมุมมองโค้ดเจ็ดภาษา ความคืบหน้าของแต่ละกรณีเก็บไว้ในเบราว์เซอร์

## เรียกใช้ FaultScope

รุ่นที่เผยแพร่สามารถเรียกด้วย `./faultscope` หากต้องการสร้างรุ่นตัวอย่างปัจจุบันจากซอร์สโค้ด ให้เรียก:

```bash
go run ./tools build
./dist/faultscope
```

เปิด [http://localhost:8080/](http://localhost:8080/) ค่าเริ่มต้น `:8080` รับการเชื่อมต่อจากทุกอินเทอร์เฟซเครือข่าย ใช้ `./dist/faultscope --listen 127.0.0.1:9000` หรือ `FAULTSCOPE_LISTEN=127.0.0.1:9000` เพื่อเปลี่ยนที่อยู่ โดยตัวเลือกบรรทัดคำสั่งมีลำดับความสำคัญกว่า การสร้างจากซอร์สต้องใช้ Node 24 และ pnpm 12 โปรดดู[คู่มือนักพัฒนา](docs/development/getting-started.md)

## สถานะและสถาปัตยกรรม

ขณะนี้เป็น **รุ่นตัวอย่าง `0.0.x`** ซึ่งเผยแพร่กรณี 01–08 แล้ว ตัวอย่าง VM งาน คำสั่งซื้อ ข้อความ และรางวัลเป็นแบบจำลองเพื่อการเรียนรู้ ไม่ใช่ SDK หรือโครงสร้างพื้นฐานสำหรับระบบจริง ทั้ง 20 ภาษามีข้อความของส่วนติดต่อและทั้งแปดกรณีครบถ้วน แต่คำแปล 19 ภาษาที่ไม่ใช่อังกฤษยังเป็น **รุ่นเบตาที่ยังไม่ได้ตรวจโดยผู้เชี่ยวชาญเจ้าของภาษา** ภาษาในส่วนติดต่อกับมุมมองโค้ดเลือกแยกกันได้ มุมมองโค้ดเจ็ดภาษา ได้แก่ **Go, TypeScript, Python, Java, PHP, C, C++** ส่วนติดต่อ Next.js/React ถูกสร้างเป็นไฟล์คงที่และฝังในไฟล์ปฏิบัติการ Go เพียงไฟล์เดียว ขณะใช้งานไม่ต้องมีเซิร์ฟเวอร์ Node ฐานข้อมูล โฟลเดอร์เนื้อหา หรือบริการแปลภาษา การตั้งค่าและความคืบหน้าเก็บเฉพาะในเบราว์เซอร์
